# نظام اعتياد — React + Vite (Client-Side Only)

تطبيق توليد شهادات يعمل بالكامل داخل المتصفح، بدون أي Backend.

## الأوضاع الأربعة

| الوضع | متى تستخدمه | المسار |
|---|---|---|
| **⚙️ أتمتة** | دفعة شهادات لعدد من الأشخاص | قالب + إكسل → حقول مربوطة بالأعمدة → PNG/PDF/ZIP |
| **✍️ يدوي** | صورة واحدة تريد كتابة نص عليها وتصديرها | صورة + طبقات نصية تحرّرها كمحرر مصغّر → PNG/PDF |
| **✂️ قص جماعي** | تطبيق إطار/شعار PNG واحد على مجموعة صور دفعة واحدة | قالب PNG + حتى 30 صورة → قص كل صورة لأبعاد القالب + تركيبه فوقها → ZIP واحد |
| **📝 نصوص** | توليد نص منشور بالذكاء الاصطناعي بتاريخ اليوم الصحيح | توجيهاتك + مفتاح Groq API خاص بك → نص جاهز للنشر |

### وضع نصوص المنشورات (Groq)

- **مفتاح API لا يُخزَّن في الكود إطلاقاً.** كل مستخدم يُدخل مفتاحه الخاص من
  [console.groq.com](https://console.groq.com)، ويُحفَظ في `localStorage` الخاص بمتصفحه
  فقط، ويُرسَل مباشرة من متصفحه إلى Groq — بلا أي خادم وسيط، فيبقى التطبيق "بلا Backend"
  تماماً كبقية الأوضاع. عند نشر الموقع علناً، كل زائر يحتاج مفتاحه الخاص.
- **تاريخ اليوم الحقيقي مُحقَن تلقائياً**: النماذج اللغوية لا تعرف التاريخ الحالي من
  تلقاء نفسها، فيُضاف اليوم واسمه (بالتقويم الميلادي عبر `Intl.DateTimeFormat`) إلى
  الطلب المُرسَل تلقائياً في كل مرة — فلا يخترع النص تاريخاً خاطئاً أبداً.
- **متغيّرات `{{التاريخ}}` و`{{اليوم}}`**: تُستخدَم داخل صندوق التوجيهات (بالكتابة أو
  بزرّي الإدراج السريع)، وتُستبدَل بالقيمة الحقيقية قبل الإرسال، ومرة أخرى على الناتج
  احتياطاً إن كرّرها النموذج حرفياً.
- **الناتج قابل للتحرير** مباشرة في مساحة العمل، مع نسخ بضغطة واحدة أو تنزيل كملف `.txt`.
- **معالجة أخطاء واضحة بالعربية**: مفتاح غير صحيح (401)، تجاوز الحد المسموح (429)،
  انقطاع الاتصال — كل حالة برسالة مفهومة بدل خطأ تقني.
- محرك الاستدعاء (`postsApi.js`) خفيف جداً (fetch عادي بلا مكتبات) فلا حاجة لتحميله
  كسولاً كبقية المحركات الثقيلة.

### وضع القص الجماعي

- **القص بمنطق `object-fit: cover`**: كل صورة تُكبَّر حتى تغطي أبعاد القالب كاملةً ثم يُقتَطع
  الزائد من المنتصف — بلا أي تمديد يُشوِّه أبعادها الأصلية. صورة أفقية عريضة تُقصّ من
  الجانبين، وصورة رأسية طويلة تُقصّ من الأعلى والأسفل، والمحتوى المركزي يبقى محفوظاً دائماً.
- **القالب فوق الصورة**: يُركَّب القالب (يُفضَّل PNG بخلفية شفافة كإطار/شعار) فوق كل صورة
  بعد قصّها — نفس ترتيب طبقات الصور في الوضع اليدوي.
- **حد أقصى 30 صورة** (`CROP_MAX_IMAGES` في `store.js`) — رفع عدد أكبر يُضيف أول 30 فقط
  مع تنبيه واحد، بلا رفض العملية بالكامل.
- **معاينة حية**: مساحة العمل تعرض القالب مركَّباً فوق أي من صورك المرفوعة فعلياً (لا رسم
  تخميني)، مع تنقّل ◀▶ بين الصور للمعاينة قبل التصدير.
- **محرك مستقل وأخف**: `cropExporter.js` منفصل تماماً عن محرك الشهادات — لا خطوط، لا نص،
  فمعالجة متسلسلة على الخيط الرئيسي كافية (بلا Worker) مع نفس الحماية: بث ZIP حقيقي
  (`zipStream.js` نفسها)، تقرير أخطاء لكل صورة مع "إعادة المحاولة للفاشلة فقط"، ولا تنزيل
  قبل الاكتمال. يُحمَّل عند أول استعمال فعلي فقط (~3KB)، بمعزل عن حزمة jsPDF الثقيلة التي
  لا يحتاجها إطلاقاً.
- **تحقّق فعلي بالبكسل**: صورة أفقية 1600×900 وأخرى رأسية 900×1600 قُصّتا لـ800×800 (أبعاد
  القالب) — المحتوى المركزي (مربع أبيض/شريط أرجواني) بقي في المركز تماماً، والحواف
  (أشرطة حمراء/خضراء عمداً) اختفت، والقالب الذهبي ظهر فوقها بدقة.

### الوضع اليدوي كمحرر طبقات

- **لوحة طبقات**: الأعلى في القائمة = الأمامي على الصورة. لكل طبقة: إظهار/إخفاء 👁،
  رفع/إنزال ▲▼، تكرار ⧉، حذف ✕. إعدادات الطبقة تُفتح للمحددة فقط.
- **تراجع/إعادة** (Ctrl+Z و Ctrl+Y): السحب المتواصل يُسجَّل كخطوة واحدة لا عشرات،
  وتحريك نفس الشريط خلال ثانية يُدمج في خطوة واحدة (`pushHistory` بمفتاح تجميع).
- **اختصارات**: الأسهم للتحريك (Shift ×10) · Ctrl+D تكرار · Delete حذف · Esc إلغاء التحديد.
- **نص متعدد الأسطر**: Enter داخل مربع المحتوى. المعاينة `white-space: pre`،
  والتصدير يرسم كل سطر على `baseline + i × lineHeight` بنفس القياس المأخوذ من المتصفح.
- **حد خارجي (Stroke)**: `-webkit-text-stroke` في المعاينة و `strokeText` بعد `fillText`
  في التصدير — نفس الترتيب فنفس النتيجة.
- **توسيط دقيق**: زرّا التوسيط الأفقي/العمودي يحسبان الموضع من ارتفاع الصندوق الحقيقي
  المقيس من المتصفح، لا بالتقريب.
- **خطوط التقاط (Snapping)**: عند السحب قرب منتصف الصورة يلتقط الموضع ويظهر خط ذهبي.
- **طبقات صور**: زر «إضافة طبقة صورة» يضيف شعاراً/توقيعاً/ختماً فوق الصورة الأساسية،
  بنفس منظومة الطبقات (سحب، تحجيم بقفل نسبة الأبعاد، شفافية، دوران، ظل حقيقي عبر
  Canvas `shadowBlur/Offset`)، ويُصدَّر بدقة مطابقة للمعاينة.

## التجاوب (سطح المكتب / آيباد / هاتف)

| العرض | التخطيط |
|---|---|
| > 1180px | شريط جانبي 480px ثابت جنباً إلى جنب مع مساحة العمل |
| 901–1180px (آيباد أفقياً، لابتوب صغير) | نفس التخطيط بشريط أضيق (340px) |
| ≤ 900px (هاتف، آيباد عمودياً) | الشريط يتحول إلى **درج** ينزلق من الحافة اليمينية فوق مساحة العمل كاملة الشاشة، بزر عائم للفتح/الإغلاق وخلفية معتمة تُغلقه بالنقر خارجه |

أهداف اللمس (المقابض، الأزرار) تكبر تلقائياً على أي جهاز لمسي عبر
`@media (pointer: coarse)`، بصرف النظر عن عرض الشاشة.

الوضعان يتشاركان **نفس لوحة الإعدادات المتقدمة بالكامل** (الخط، الحجم، اللون، العريض،
المحاذاة، التباعد، الشفافية، الدوران، الظل، الموضع) ونفس محرك الرسم — الفرق الوحيد أن نص
الحقل في الأتمتة يأتي من عمود إكسل، وفي اليدوي يكتبه المستخدم. حقول كل وضع تُحفظ على حدة
عند التبديل، والصورة المرفوعة مشتركة بينهما.

## النشر أونلاين (استضافة ثابتة بلا خادم)

```bash
npm run build
```

الناتج كله في مجلد `dist/` — ملفات HTML و JS و CSS ثابتة فقط. لا Backend ولا أي إعداد
على الخادم؛ المتغيّران الوحيدان (`VITE_SUPABASE_*`) يُقرآن وقت البناء لا وقت التشغيل،
وقاعدة البيانات خدمة خارجية (Supabase) يخاطبها المتصفح مباشرة.

| الاستضافة | الطريقة |
|---|---|
| **Netlify** | اسحب مجلد `dist` إلى [app.netlify.com/drop](https://app.netlify.com/drop) |
| **Vercel** | `npx vercel deploy dist --prod` |
| **GitHub Pages** | مُهيَّأ تلقائياً في هذا المستودع — انظر القسم التالي |
| **Cloudflare Pages** | أمر البناء `npm run build`، ومجلد الإخراج `dist` |
| **استضافة عادية / cPanel** | ارفع محتويات `dist` إلى `public_html` (أو أي مجلد فرعي) |

`base: './'` في [vite.config.js](vite.config.js) يجعل كل المسارات نسبية، فيعمل الموقع من
جذر النطاق أو من مجلد فرعي (`example.com/eatiad/`) بلا أي تعديل. ولأن الصفحة واحدة بلا
توجيه (routing) فلا حاجة لأي قاعدة إعادة كتابة (rewrite) على الخادم.

**للتجربة قبل النشر:** `npm run preview` يشغّل ناتج البناء نفسه على `localhost:4173`.

### النشر التلقائي على GitHub Pages

[`.github/workflows/deploy.yml`](.github/workflows/deploy.yml) يبني الموقع وينشره عند كل
دفعة إلى `main`. لا حاجة لأي خطوة يدوية ولا لفرع `gh-pages`.

الموقع المنشور: <https://abdarhemsheet-max.github.io/nizam-eatiad/>

مفتاحا Supabase لا يوجدان في الشيفرة — يُحقنان وقت البناء من **أسرار المستودع**
(Settings ← Secrets and variables ← Actions):

| السر | القيمة |
|---|---|
| `VITE_SUPABASE_URL` | `https://<project-ref>.supabase.co` |
| `VITE_SUPABASE_ANON_KEY` | المفتاح العام (publishable) وحده |

المفتاح العام مُصمَّم أصلاً ليعمل داخل المتصفح ولا ضرر في ظهوره في ملفات البناء؛ ما
يحمي البيانات هو سياسات RLS في قاعدة البيانات، لا إخفاء المفتاح. **مفتاح الخدمة
(`service_role` / `sb_secret_…`) لا يُوضع هنا ولا في أي مكان يصل إليه المتصفح.**

### ملاحظات تشغيلية

- **الخصوصية:** لا يُرفع أي ملف إلى أي خادم. الصور والإكسل تُقرأ وتُعالَج داخل المتصفح،
  والتنزيل يتم من الذاكرة مباشرة عبر Blob.
- **الاتصال بالإنترنت** مطلوب لتحميل ملفات التطبيق وخطوط Google أول مرة فقط، ثم يعمل
  من الكاش. (خطوط الجهاز تعمل بلا إنترنت أصلاً.)
- **لا يعمل بفتح `index.html` مباشرة من القرص** (بروتوكول `file://` يمنع وحدات ES).
  يحتاج أن يُقدَّم عبر HTTP — وهذا ما تفعله أي استضافة.
- **المتصفحات:** Chrome / Edge 99+، Safari 17.4+، Firefox 129+ (بسبب `ctx.letterSpacing`).
  في المتصفحات الأقدم يعمل كل شيء عدا التباعد بين الأحرف في الملف المُصدَّر.
- **لا حفظ تلقائي:** يظهر تحذير المتصفح عند إغلاق التبويب إذا كان هناك عمل قائم.

## قاعدة البيانات (Supabase)

المخطط كله موصوف في [`supabase/migrations/`](supabase/migrations) ويُطبَّق بأمر واحد:

```bash
supabase link --project-ref <project-ref>
supabase db push
```

ما ينشئه المخطط:

| العنصر | الغرض |
|---|---|
| جدول `public.projects` | المشروع المحفوظ: مسار القالب، الحقول (`jsonb`)، الوضع، التكبير |
| مخزن `templates` | صور القوالب، بمسار `<user_id>/<filename>` وحد 20 ميغابايت للصورة |
| سياسات RLS | كل مستخدم يقرأ ويكتب صفوفه ومجلده وحدها |

`user_id` قيمته الافتراضية `auth.uid()`، فالواجهة تُدرج الصف بلا هوية وتضبطها قاعدة
البيانات من الجلسة نفسها — لا يستطيع مستخدم أن ينسب مشروعاً لغيره.

**للتطوير المحلي:** انسخ [`.env.example`](.env.example) إلى `.env` واملأه بمفاتيح مشروعك.
الملف مستثنى في `.gitignore`.

## قرار معماري: نظام الإحداثيات

الحقول تُخزَّن بـ **بكسل الصورة الأصلية** (natural pixels)، لا ببكسل الشاشة:

- مساحة العمل ترسم الصورة بحجمها الطبيعي، والتكبير مجرد `transform: scale()` بصري.
- عند السحب: `dx / zoom` → الإزاحة بإحداثيات الصورة مباشرة.
- عند التصدير (المرحلة الثالثة): الرسم على Canvas بحجم الصورة الأصلي يكون مطابقة 1:1، بلا أي معادلات تحويل أو قياس `getBoundingClientRect`.

## مطابقة المعاينة للمخرَج (WYSIWYG)

ثلاث نقاط تضمن أن ما تراه في المعاينة هو ما يخرج بالضبط:

1. **لا إزاحة من الصندوق:** `.preview-text` يستخدم `outline` + `outline-offset` بدل
   `border` + `padding`، و outline لا يؤثر على التخطيط. لذا `(x, y)` المخزّنة هي
   نفسها نقطة الرسم على Canvas.
2. **خط الأساس (baseline) مقيس من المتصفح:** بدل تخمين ارتفاع الصعود، ينشئ المحرك عنصراً
   مطابقاً للمعاينة ويقيس موضع خط الأساس فيه (`measureLineMetrics`). الفرق المقاس بين
   المعاينة والناتج أقل من بكسل واحد.
3. **المحاذاة = نقطة إرساء:** `align` في المعاينة يُطبَّق بـ `translateX`، وعند التصدير
   بـ `ctx.textAlign` — وكلاهما فيزيائي، فيتطابقان تماماً. هذا ما يجعل الأسماء المختلفة
   الأطوال تبقى متمركزة على نفس النقطة.

## المراحل

- **M1 — التخطيط والمخزن:** ✅ منجز
- **M2 — الرفع والسحب والإفلات:** ✅ منجز
- **M3 — محرك التوليد:** ✅ منجز
  - PNG: تصدير بلا فقد (lossless) **مع الحفاظ على شفافية القالب** — الكانفاس
    يُمسح بـ `clearRect` بلا خلفية، فما كان شفافاً في القالب يبقى شفافاً في الناتج.
  - PDF: صفحة بحجم القالب تماماً، مع خيار دمج كل الشهادات في ملف واحد.
    صور صفحات الـ PDF تُرمَّز JPEG بجودة 0.95 (ثابت `PDF_JPEG_QUALITY` في
    `exporter.js`) لتفادي انفجار حجم الملف والذاكرة في الدفعات الكبيرة —
    غيّرها إلى PNG إن كانت الجودة القصوى أهم من الحجم.
    ولأن JPEG لا يدعم الشفافية، تُضاف خلفية بيضاء *خلف* المحتوى
    (`destination-over`) بعد التقاط الـ PNG مباشرة — فلا يتأثر PNG بها.
  - ZIP: يجمع المخرجات في مجلدات `PNG/` و `PDF/`.
  - نافذة تقدّم لحظية مع إلغاء بين شهادة وأخرى.
- **M4 — محرك دفعي بلا حدود عملية (Web Worker + بث حقيقي):** ✅ منجز

### M4 — كيف يُنتِج المحرك 200+ شهادة بأقل ذاكرة ممكنة

المشكلة الأصلية: `JSZip.generateAsync()` يحتاج كل الملفات جاهزة في الذاكرة *قبل*
أن يبدأ الضغط، وكانت هذه هي العنق الحقيقي أمام دفعات كبيرة — لا الرسم نفسه.
الحل: استبدال JSZip بـ [fflate](https://github.com/101arrowz/fflate) بنمط
البث (`Zip` + `ZipPassThrough`)، بحيث يُضاف كل ملف فور جهوزيته ويُحرَّر مرجعه
مباشرة — لا "تجميع كل الشهادات ثم الضغط".

**خط الأنابيب لكل صف:**

```
صف إكسل → عامل متفرّغ → OffscreenCanvas.drawImage/fillText → PNG Blob
        → (اختياري) JPEG بخلفية بيضاء → jsPDF على الـ Main Thread
        → إضافة فورية لأرشيف ZIP المتدفق → تحرير كل المراجع → الصف التالي
```

- **تجمّع عمّال محدود (`workerPool.js`)**: 2-4 عمّال حسب أنوية الجهاز
  (`navigator.hardwareConcurrency`)، يهبط تلقائياً إلى عامل واحد إن كانت
  `navigator.deviceMemory` ≤ 2GB. كل شهادة تُرسَل لأول عامل متفرّغ، فلا يمكن
  إطلاقاً أن تُرسَم أكثر من N شهادة في نفس اللحظة.
- **الرسم داخل Worker حقيقي (`certWorker.js` + `canvasText.js`)**: يستخدم
  `OffscreenCanvas`، فلا يُجمَّد الـ Main Thread (شريط التقدم وزر الإلغاء يبقيان
  حيّين). القياسات تعتمد `TextMetrics.fontBoundingBoxAscent/Descent` بدل تخطيط
  DOM (غير متاح داخل Worker) — نفس الدقة، مصدرها نفس جداول الخط.
- **توليد PDF يبقى على الـ Main Thread عمداً**: jsPDF غير مصمَّمة صراحة لسياق
  Worker. بدل المخاطرة، يُنتج العامل صورة JPEG جاهزة فقط، والـ Main Thread
  يُغلّفها بـ jsPDF — تغليف بايتات خفيف لا رسم، فلا يُجمّد الواجهة.
- **بلا Base64**: كل تمرير للبيانات (Worker↔Main، jsPDF، ZIP) عبر
  `Blob`/`Uint8Array` مباشرة، لا `canvas.toDataURL()`.
- **ترتيب PDF المدمج**: العمّال يكتملون خارج ترتيب الصفوف (تسابق طبيعي)، فمخزن
  ترتيب صغير (`pdfBuffer` + `nextFlushIndex`) يُدرج الصفحات في جسم الـ PDF
  بترتيبها الأصلي دائماً — بما في ذلك تخطّي الصفوف الفاشلة دون أن يعلق الترقيم
  (خلل حقيقي اكتُشف وأُصلح أثناء الاختبار: فشل صف واحد كان يُسقط كل الصفحات
  اللاحقة بصمت).
- **معالجة الأخطاء لا توقف الدفعة**: صف فاشل يُسجَّل ويُتابَع الباقي. تقرير
  نهائي "تم إنشاء X / فشل Y" مع زر **إعادة توليد الفاشلة فقط** (أرشيف جديد
  منفصل بالصفوف الفاشلة حصراً).
- **لا تنزيل قبل الاكتمال**: الأرشيف يُبنى بالكامل أولاً؛ زر **تحميل ZIP**
  صريح يظهر فقط بعد الانتهاء — لا تنزيل تلقائي.
- **حفظ مباشر على القرص (اختياري)**: خيار "حفظ مباشر على القرص" (يظهر في
  Chrome/Edge فقط) يستخدم File System Access API فيكتب الأرشيف مباشرة بلا أي
  حد لحجمه، بدل تجميعه في ذاكرة التبويب. الاختيار يُطلَب من المتصفح ضمن بادرة
  ضغطة الزر مباشرة في `Sidebar.jsx` (شرط متصفّحي)، قبل أي `await` آخر.
- **قياس فعلي**: 200 شهادة (قالب 1600×1100px، PNG + PDF مدمج) على بناء الإنتاج
  الحقيقي: **~44 ثانية، ذروة ذاكرة ~12MB إضافية فقط**، أرشيف 14.7MB صحيح
  بالكامل (201 ملف: 200 PNG + PDF مدمج بـ200 صفحة بالترتيب الصحيح).

### ملاحظات تشغيلية

- بدون ZIP يتم تنزيل كل ملف على حدة، وقد يحجب المتصفح التنزيلات المتلاحقة —
  لذلك يظهر تأكيد عند تجاوز 15 ملفاً.
- **ملاحظة بناء مهمة (Vite + Web Worker)**: `new URL('./certWorker.js', import.meta.url)`
  يجب أن يبقى **ملاصقاً مباشرة** لاستدعاء `new Worker(...)` في نفس الملف
  (`workerPool.js`). تمريره كقيمة جاهزة من ملف آخر ينجح في `npm run dev` فقط
  ويفشل في `npm run build` بخطأ MIME type (Vite لا يستطيع إعادة كتابة المسار
  إلى اسم الملف المُجزَّأ hashed إن كان البناء مفكَّكاً عبر ملفين) — خلل حقيقي
  اكتُشف وأُصلح أثناء اختبار البناء الإنتاجي، فتأكد من عدم تفريقه مرة أخرى.
